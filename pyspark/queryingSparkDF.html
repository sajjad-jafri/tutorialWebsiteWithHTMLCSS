In this lecture, we will query on the Spark Dataframe.


To query the DF, we have 2 approach:

  • SQL Approach

  • Dataframe Transformation Approach



SQL Approach

The SQL approach is a two step process:

  • Convert your Dataframe to a temporary view

  • Run your SQL on the view


Let's start with creating a fire_df dataframe first

fire_df = spark.read \
    .format("csv") \
    .option("header", "true") \
    .option("inferSchema", "true") \
    .load("/databricks-datasets/learning-spark-v2/sf-fire/sf-fire-calls.csv")

Now, we will convert our Dataframe to a temporary view.

fire_df.createOrReplaceTempView("fire_service_calls_view")

The createOrReplaceTempView() is a utility method, and it takes the view name as an argument. This method will create a temporary view. Once you have a temporary view, you can use SQL on the view.


Before running the sql on the Temp view, Let's see the queries which we have used in earlier chapters (querying with Spark Table).

Q1. How many distinct types of calls were made to the fire department?

select count(distinct CallType) as distinct_call_type_count
	from demo_db.fire_service_calls_tbl
	where CallType is not null

This is same query we can use in spar.sql() method as below:

fire_df.createOrReplaceTempView("fire_service_calls_view")
q1_sql_df = spark.sql("""
            select count(distinct CallType) as distinct_call_type_count
            from fire_service_calls_view
            where CallType is not null          
                      """)
display(q1_sql_df)

Output

32


So we have used the same SQL that we used on the table. But we changed the table name to the view name.


The spark.sql method takes a SQL expression, executes the SQL, and returns the result into a new dataframe. So q1_sql_df is the DF from result of the SQL query.


So we learned to run analysis queries on a dataframe. It is a two-step process:

  • The first step is to create a view of your dataframe.

  • The second step is to run SQL queries on the view. The second step will give you a dataframe.


We can take that dataframe for further analysis or simply display it. This is one easy way to use Spark for those who are more comfortable using SQL queries.


Now, we will use the second approach - Dataframe Transformation Approach



Dataframe Transformation Approach

Before writing the code, let's build the logic:

  • Filter the records and take only those where CallType is not null

  • select the CallType column

  • Take only distinct call types

  • And finally show the count


Let's write a code

q1_df = fire_df.select("CallType") \
        .where("CallType is not null") \
        .distinct()
print(q1_df.count())

We are calling a chain of three methods and each method represents one step of logic.


We have used 3 transformation method:

  • where()

  • select()

  • distinct()

They are transformations because they return a dataframe, and we can chain one or more transformations together.


We used 1 action method:

  • count()

Action doesn't return a dataframe. It returns the result to the driver.



Let's look at the second question and the query we used in table for earlier chapter (querying with Spark Table).


Q2. What are distinct types of calls made to the fire department?

select distinct CallType as distinct_call_type
	from demo_db.fire_service_calls_tbl
	where CallType is not null

Now look at the code for querying the Dataframe

q2_df = fire_df.select("CallType") \
        .where("CallType is not null") \
        .distinct()
display(q2_df)

will give you the output as 32 different calltype.



Q3. Find out all responses for delayed times greater than 5 mins?

SQL:
select CallNumber, Delay
	from demo_db.fire_service_calls_tbl
	where Delay > 5
			

Dataframe Transformation:
q3_df = fire_df.select("Call Number", "Delay") \
        .where("Delay > 5") \
        .show()


Q4. What were the most common call types?

SQL:
select CallType, count(*) as Count
from demo_db.fire_service_calls_tbl
	where CallType is not null
	group by CallType
	order by Count desc
			

Dataframe Transformation:
q4_df = fire_df.select("CallType") \
    .where("CallType is not null") \
    .groupBy("CallType") \
    .count() \
    .orderBy("count", ascending=False) \
    .show()

Output

Note:If count is used after groupBy then it is a Transformation, not an action.

We have two count() methods in Spark. DataFrame.count() and GroupedData.count()

If you are using a count before the groupBy(), it will be an action

However, if you use a count() method after the groupBy(), it will be a transformation
